# Sprint 3 — Маркетинговые материалы для Битрикс24 Маркетплейс

**Дата**: 2026-04-26
**Цель**: подготовить полный комплект документов для публикации приложения «Согласование в чате» в Битрикс24 Маркетплейс.
**Длительность**: ~2 часа.
**Стратегия**: 1 ключевой MCP-запрос (`bitrix-search`) + 2 детали (`monetization`, `IM_TEXTAREA icon`) → 9 целевых документов в `docs/ru/marketplace/`.

---

## 1. Контекст

После Sprint 2.3 у проекта были закрыты P0/P1 баги и поднят CI. Следующий шаг — собрать материалы для модерации, не выпуская релиз раньше, чем готовы тексты, визуальный бриф и юридические документы.

---

## 2. MCP-исследование требований

| Запрос | Результат |
|--------|-----------|
| `bitrix-search "требования к публикации приложения в маркетплейсе"` | 15 релевантных статей; выделены 5 ключевых |
| `bitrix-article-details "Условия участия в подписке Битрикс24 Маркетплейс"` | Полный регламент монетизации; выделены 4 критерия для статуса «Монетизируемое» |
| `bitrix-article-details "Создать иконку Приложения для чата"` | Точные параметры иконки `IM_TEXTAREA`: 108×66, прозрачный фон, цвета #B3B7BC/#2FC7F7, base64 в `ICON_FILE` |

> Все требования зафиксированы в `requirements-checklist.md` со ссылками на источники. Это позволяет в дальнейшем проверять диффом, что регламент Битрикс24 не поменялся.

---

## 3. Что сделано

### 3.1 Требования и чек-лист
**Файл**: `docs/ru/marketplace/requirements-checklist.md` (~280 строк).

Покрывает:
- Регион публикации (RU старт, BY/KZ потом).
- Контрагент: УСН + ОКВЭД 62/63 + ЭДО.
- Карточка решения: 12 текстовых полей + ограничения.
- Карточка версии: scope, тип решения, опции встройки, тариф.
- Технические требования: OAuth, HTTPS, REST-кэш, batch, логи.
- Условия непубликации (наш self-check).
- Таймлайн модерации.

### 3.2 Позиционирование
**Файл**: `positioning.md` (~210 строк).

- Слоган + 3 буллета.
- ICP: размер компании, тариф, отрасли, роли, триггеры.
- Job-to-be-Done.
- Конкурентный анализ (БП Битрикс24, ECM, Slack-аналоги).
- Tone of voice + язык.
- Сообщения по аудитории (3 роли).
- Антипаттерны («что не делаем»).

### 3.3 Тексты для карточки
**Файл**: `copy.md` (~290 строк).

- 3 варианта названия + код приложения `vendor.chat-approval`.
- 3 варианта слогана.
- Полное описание ~1450 символов (в пределах рекомендации 800–1500).
- Ключевые слова ~850 символов (под лимит 2000).
- Описание процесса установки.
- Шаблон поля «Поддержка».
- Заготовка «Что нового» для версий.
- SEO-ключи и микро-копи для скриншотов.
- Чек-лист корректности перед сабмитом.

### 3.4 Бриф визуальных материалов
**Файл**: `visuals-brief.md` (~265 строк).

- Иконка для каталога Маркетплейса (512×512).
- Иконка для `IM_TEXTAREA` (108×66, по точным требованиям из MCP).
- Аватар бота (200×200).
- 8 скриншотов с описанием состояния и подписью.
- Промо-баннеры (1920×800 и 1200×630).
- Сценарий видео-демо 30–60 сек.
- Палитра, шрифты, антипаттерны.
- Сроки и этапы работы дизайнера.

### 3.5 Юридические документы
**Папка**: `legal/` (4 файла, ~700 строк суммарно).

- `README.md` — навигация и предупреждение о юр.проверке.
- `eula.md` — лицензионное соглашение, 11 разделов, плейсхолдеры для реквизитов.
- `privacy-policy.md` — политика конфиденциальности, 12 разделов, явная stateless-аргументация для 152-ФЗ.
- `pdn-consent.md` — согласие на обработку ПДн (для лендинга).
- `terms-summary.md` — сводная памятка для продакта/менеджера.

> Все шаблоны помечены «требуют юр.проверки». Реквизиты, ОГРН, домены — через плейсхолдеры `{{...}}`.

### 3.6 Ценовая политика
**Файл**: `pricing.md` (~190 строк).

- TL;DR: подписка Маркетплейса, статус «Монетизируемое», без доплат.
- Альтернативные модели и почему отвергнуты.
- Соответствие 4 критериям статуса «Монетизируемое» (из MCP-результата).
- Перечень основного функционала (защита от «формального» сценария).
- План платных расширений на будущее (после 6 мес).
- Финансовая модель и целевые метрики на старте.
- Антипаттерны.

### 3.7 Манифест приложения
**Файлы**: `/app.json` (в корне) + `manifest-guide.md` (в marketplace/).

`app.json`: 80 строк JSON с полями code, name, version, scope, placements, events, bot, entity_storages, limits, monetization, compliance, support, legal, categories, tags, regions. Плейсхолдеры `__APP_DOMAIN__`/`__VENDOR_DOMAIN__`.

`manifest-guide.md` (~135 строк): объясняет, что Битрикс24 не использует app.json напрямую, но он — single source of truth + чек-лист маппинга в кабинет разработчика + план CI-валидации (Sprint 4).

### 3.8 Поддержка
**Файл**: `support.md` (~245 строк).

- 5 каналов поддержки с ролями.
- Регламент: часы работы, SLA P1–P4, аптайм 99.5%.
- FAQ из 18 вопросов (установка, использование, файлы, безопасность, биллинг, развитие).
- Внутренний регламент саппорта: 3 шаблона ответов, чек-лист саппорт-инженера, что запрещено.
- Целевые метрики саппорта.

### 3.9 Submission-чек-лист
**Файл**: `submission-checklist.md` (~205 строк).

13 разделов (A–M):
- Контрагент и ЭДО.
- Юр.документы.
- Текстовые поля карточки.
- Визуальные материалы.
- Технические настройки версии.
- Ценовая политика.
- Тестовые сценарии.
- Браузеры и устройства.
- Безопасность.
- Качество кода и CI.
- FAQ и status-page.
- Финальные действия.
- Запасной план.

Со sigout-ролями: продакт, техлид, юрист.

### 3.10 Дизайн-ассеты (baseline)

**Папка**: `assets/marketplace/` (4 SVG + preview.html + README.md).

Концепция: чат-баббл с зелёной галочкой согласования + бренд-палитра `#2FC7F7 / #37BB72 / #FF5752 / #B3B7BC / #F4F6F8`.

| Файл | Что |
|------|-----|
| `icon-marketplace-512.svg` | Иконка приложения 512×512 для карточки Маркетплейса (не прозрачный фон, по регламенту) |
| `icon-textarea-108x66.svg` | Иконка `IM_TEXTAREA` 108×66 с двумя зонами: inactive `#B3B7BC` слева + active `#2FC7F7` справа, прозрачный фон, по регламенту <https://apidocs.bitrix24.ru/api-reference/chats/outdated/icon.html> |
| `bot-avatar-200.svg` | Аватар бота 200×200 с галочкой-«ртом», другой визуальный язык (чтобы пользователь различал «кликабельный виджет» и «отправителя сообщений») |
| `promo-banner-1920x800.svg` | Промо-баннер с слоганом, мокапом чата и кнопками голосования. Кадрируется под 1200×630 (OG) и 1080×1080 |
| `preview.html` | Открывается в браузере, показывает палитру + все ассеты + микро-копи + финальный pack-list |
| `README.md` | Инструкция по конвертации SVG→PNG (`rsvg-convert`, Inkscape, web-конвертеры) и направления улучшения для дизайнера |

Все 4 SVG прошли XML-валидацию (`python3 -c "import xml.etree.ElementTree as ET; ET.parse(...)"`).

> ⚠️ Это **baseline** — функциональный комплект, чтобы не блокировать сабмит модерации до найма дизайнера. Дизайнер принимает эти файлы как стартовую точку и улучшает по направлениям, перечисленным в `assets/marketplace/README.md` пункт «Что осталось сделать дизайнеру».

## 7. Краткий итог

Sprint 3 закрыт. Все 9 целевых артефактов плана подготовлены; 1 ключевая MCP-проверка регламента сделана; реквизиты и ассеты вынесены в плейсхолдеры/бриф, чтобы не блокировать работу до согласований с юристом и дизайнером.

После заполнения плейсхолдеров и подготовки визуальных ассетов можно идти в кабинет 1С-Битрикс и заполнять карточку решения. До этого нужен **Sprint 4** (Timeweb-деплой), чтобы у `__APP_DOMAIN__` появился рабочий backend по реальному URL.
