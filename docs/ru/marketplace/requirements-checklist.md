## 1. Регион публикации

| Регион | Решение | Обоснование |
|--------|---------|-------------|
| **Россия (RU)** | ✅ Стартуем здесь | Основная аудитория — русскоязычные команды |
| Беларусь (BY) | После RU | После прохождения модерации в RU подача почти бесплатная |
| Казахстан (KZ) | Опционально | В KZ доступна только бесплатная публикация — несовместимо с подпиской в RU |
| Запад (EN) | Не сейчас | Требует полного перевода UI/документов и поддержки на международных доменах |

> **Жёсткое ограничение FAQ**: одно и то же приложение нельзя опубликовать «по подписке в RU» и «бесплатно в KZ» — нужно создавать два разных приложения с разными `app_code`.

## 2. Контрагент (для платной публикации в RU/BY)

- [ ] Действующее российское юр.лицо или ИП.
- [ ] **УСН** (Упрощённая система налогообложения).
- [ ] **ОКВЭД 62 или 63** (разработка ПО).
- [ ] Без проблем при ФНС-проверке.
- [ ] Подключён ЭДО (Диадок или роуминг к Диадок).

> ❌ Самозанятые (НПД) и ПСН не принимаются.
> ❌ ИП на ОСНО — отдельное согласование.

## 3. Карточка решения (поля)

### 3.1 Название
- [ ] Ёмкое, понятное; не «Тестовое приложение №1».
- [ ] Запрещены: упоминания брендов 1С-Битрикс / Bitrix24 как часть названия.

### 3.2 Категории (до 5)
Для нашего приложения подходят:
- **«Совместная работа — Чаты»** (основная — мы расширяем мессенджер).
- **«Автоматизация — Задачи и проекты»** (опционально — согласования = workflow).
- **«Разное»** **не использовать** — есть подходящая категория.

### 3.3 Теги (до 5, для подборок)
Кандидаты: «согласование», «голосование», «командная работа», «бизнес-процессы», «корпоративный мессенджер».

### 3.4 Маркетинговый слоган (1–2 предложения)
- [ ] Не дублировать название.
- [ ] Дополняет название, объясняет ценность.

### 3.5 Полное описание
- [ ] Список задач, которые решает приложение.
- [ ] **Обязательно** перечислены ограничения:
  - [ ] Минимальный тариф Битрикс24 (нужен `imbot`-scope).
  - [ ] Что устанавливать может только администратор портала (или нет).
- [ ] Никаких упоминаний скидок/акций/контактов вне дозволенных полей.
- [ ] Без грамматических ошибок (проверка «Орфо» / Grammarly).

### 3.6 Ключевые слова
- [ ] До 2000 символов.
- [ ] Реальные слова, без `Битрикс24` и брендов конкурентов.
- [ ] Через запятую.

### 3.7 Описание процесса установки
- [ ] Шаги от «нажмите Установить» до «работающее приложение».
- [ ] Где найти настройки (если есть).
- [ ] Что нужно делать, если шаг падает.

### 3.8 Информация о поддержке и обратной связи
- [ ] E-mail.
- [ ] Канал helpdesk / форма обратной связи.
- [ ] **Регламент работы**: рабочие дни/часы, время реакции.
- [ ] (Если EN-версия) — без ссылок на русскоязычные ресурсы.

### 3.9 Иконка
- [ ] **Формат**: JPEG или PNG (без прозрачного фона!).
- [ ] **Размер**: 250×250…650×650 px (квадрат).
- [ ] Без размытия и пикселизации.
- [ ] Без чужих торговых знаков и логотипов 1С-Битрикс.

> ⚠️ **Не путать** с иконкой `IM_TEXTAREA` placement (это другая иконка):
>
> - Размер холста 108×66 px (две зоны: слева inactive, справа active).
> - Основная часть до 45×32 px, отцентрирована.
> - Прозрачный фон.
> - Цвета: inactive `#b3b7bc`, active `#2fc7f7`.
> - Передаётся base64-encoded в `ICON_FILE` при `imbot.app.update`.

### 3.10 Скриншоты
- [ ] **Размер**: до 1280×720 px.
- [ ] **Формат**: JPEG или PNG.
- [ ] Полноэкранный интерфейс приложения **внутри Битрикс24** (в слайдере).
- [ ] **Реалистичные демо-данные** (не «Test User», не «foo@bar.com»).
- [ ] Если EN-версия — только англоязычные данные.

### 3.11 Лицензионное соглашение и Политика конфиденциальности
- [ ] Ссылки **на просмотр** в браузере (HTML/PDF/TXT), не на скачивание.
- [ ] Лицензионное соглашение содержит **точное название приложения** и реквизиты лицензиара.
- [ ] Политика конфиденциальности соответствует 152-ФЗ (для RU).

### 3.12 Опциональные ссылки
- [ ] Связаться с разработчиком — форма/мессенджер.
- [ ] Запросить демонстрацию — если применимо.

## 4. Карточка версии решения

### 4.1 Скоупы (разделы системы)
**Включаем только реально нужные**: `imbot`, `im`, `entity`, `disk`, `placement`, `user_basic`.

- [ ] **`user_basic`**, не `user` — нам не нужен список всех пользователей с приватной информацией; хватит базовых полей. ⚠️ Из регламента: «`Пользователи` в полной версии выдаётся только если без них невозможна работа основного функционала. В остальных случаях — только минимальный скоуп».
- [ ] Никаких «на будущее» скоупов.

### 4.2 Тип решения
- [ ] **Использовать REST API** — наш кейс.

### 4.3 Опции встройки
| Опция | У нас | Обоснование |
|-------|-------|-------------|
| Добавлять свою страницу и пункт в главном меню | ❌ нет | Чат-бот не должен иметь пункт в левом меню (явное указание регламента) |
| Встраиваться в Bitrix24 Mobile | ❌ нет (пока) | Требует адаптивности — есть, но протестируем отдельно |
| Встраивать виджеты в интерфейс | ✅ да | `IM_TEXTAREA` placement |
| Может устанавливать любой пользователь | ❓ обсудить | Сейчас нужен админ для регистрации бота. Можно ослабить, если допишем self-bind |

### 4.4 Минимальный тариф Битрикс24
- [ ] Указать: «Стандарт» или выше (для `imbot`-методов).

### 4.5 «Что нового в приложении»
- [ ] Для первой версии заполнять не нужно — берётся из описания автоматически.
- [ ] Для последующих версий — список изменений на всех языках карточки.

### 4.6 Ссылка на приложение
- [ ] HTTPS, валидный SSL (минимум DV).
- [ ] HEAD-запрос возвращает 200/301/302 (проверить через reqbin.com).
- [ ] Без редиректов, замедляющих загрузку.

### 4.7 Ссылка на установочное приложение
- [ ] HTTPS, валидный SSL.
- [ ] Авторизация через OAuth 2.0 (никогда не запрашиваем логин/пароль Битрикс24).

## 5. Технические требования к самому приложению

### Аутентификация и безопасность
- [x] **OAuth 2.0** для авторизации (не логин/пароль).
- [x] **HTTPS-only**, валидный DV-сертификат на сервере.
- [x] Сервер проходит сканер безопасности 1С-Битрикс.
- [x] Антивирусная защита на сервере.

### REST API
- [x] **Превалидация запросов** на стороне приложения.
- [x] Обработка ошибок API (без бесконечных повторов).
- [x] **Кэширование данных** (у нас: `_option_cache`, `_bot_id_cache`).
- [x] **Batch-запросы** где возможно (у нас: `user.get` через `FILTER[ID]`, ONAPPUNINSTALL bind/unbind).

### Логи
- [x] **Хранить логи REST-запросов и ответов ≥ 3 суток** — см. ROTATION в Sprint 4.

### Чат-бот
- [x] **Приветствие при добавлении в чат** с описанием функционала и команд.
- [x] **Собственный аватар** для бота.

### Демо-данные
- [ ] Никаких реальных номеров, e-mail, ссылок в скриншотах. Только постановочные данные («Иван Иванов», «ivan@example.com»).

### Установка / удаление / переустановка
- [x] Тестовый сценарий пройден (Sprint 2).
- [x] **ONAPPUNINSTALL** обработан (Sprint 2.2): возвращаем 200 OK; данные на бэкенде стирать не нужно (мы stateless).
- [x] **Переустановка**: повторный install идемпотентен (флаг `app.option["storages_ready"]` препятствует пересозданию entity).

### Безопасность данных пользователей
- [x] **152-ФЗ**: персданные пользователей не хранятся вне Bitrix24 entity клиента.
- [x] Согласие на рекламные рассылки не требуется (мы их не делаем).

## 6. Ценовая политика — наш выбор

**Целевой статус**: **«Монетизируемое»** через подписку Битрикс24 Маркетплейс.

Обоснование (по критериям из <https://apidocs.bitrix24.ru/market/monetization/index.html>):

| Критерий | Наш кейс |
|----------|----------|
| 1. Функциональная ориентированность на Битрикс24 | ✅ Мы расширяем мессенджер Битрикс24 — функционала нет вне платформы. |
| 2. Эксклюзивность | ✅ Не работаем с Slack/Teams; нет универсального продукта. |
| 3. Законченный сценарий без доплат | ✅ Без любых внешних платежей пользователь создаёт согласование, голосует, видит результат. |
| 4. Доплаты / внешние сервисы | ✅ Нет — никакие внешние SaaS / SMS / телефония не используются. |

Подробнее: `pricing.md`.

## 7. Условия непубликации (наш self-check)

Решение **не пройдёт** модерацию, если:

- [ ] ⛔ Незаполненные обязательные поля (Описание / Установка / Поддержка / иконка / скриншоты).
- [ ] ⛔ В описании — контакты вместо описания, или скидки в установке.
- [ ] ⛔ Грамматические ошибки.
- [ ] ⛔ Текст на языке, не соответствующем выбранному (например, английский в RU-карточке).
- [ ] ⛔ Скриншоты с пустыми полями, тестовыми пользователями, нулевыми отчётами.
- [ ] ⛔ Лишние scope без очевидной связи с функционалом.
- [ ] ⛔ Простой HTML-интерфейс (у нас — Vue 3 + B24UI, проходит ✅).
- [ ] ⛔ Пустой iframe при установке (у нас — мастер install.client.vue, проходит ✅).
- [ ] ⛔ Реальные демо-данные.
- [ ] ⛔ JS / PHP-ошибки в интерфейсе.
- [ ] ⛔ Полосы прокрутки во фрейме при ≥1280 px.
- [ ] ⛔ Ссылки на несуществующие страницы / битые изображения.
- [ ] ⛔ Сканер безопасности нашёл проблемы.

Минимальный гайдлайн от Битрикс24:

- [ ] Адекватное название.
- [ ] Понятное описание (что делает, как настроить, контакты).
- [ ] Видео и картинки в описании открываются, не битые.
- [ ] Хорошая иконка 250×250…650×650 px.
- [ ] Информативные скриншоты внутри Битрикс24.
- [ ] Лицензионное соглашение и политика конфиденциальности — рабочие ссылки.
- [ ] Только нужные scope.
- [ ] Места встройки виджетов указаны (у нас: `IM_TEXTAREA`).
- [ ] Тщательно протестировано.
