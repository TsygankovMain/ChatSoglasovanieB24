# Сводная памятка по юр.документам для маркетплейса

> Краткая шпаргалка для продакта/менеджера: что и как должно быть оформлено к моменту сабмита.

---

## 1. Что требует регламент Битрикс24

В карточке решения требуются **рабочие ссылки в браузере** (HTML/PDF/TXT) на:

1. **Лицензионное соглашение** (EULA).
2. **Политика конфиденциальности**.

Поле «Установить бесплатно» в подписке Маркетплейса не требует отдельных юр.документов от разработчика — ценообразование оформляет 1С-Битрикс через ЭДО.

## 2. Что у нас подготовлено

| Документ | Файл | Где публиковать |
|----------|------|-----------------|
| EULA | `eula.md` | `https://<vendor>.ru/legal/eula.html` |
| Privacy Policy | `privacy-policy.md` | `https://<vendor>.ru/legal/privacy.html` |
| Согласие на ПДн | `pdn-consent.md` | На лендинге, в форме обратной связи |

## 3. Технология публикации

**Самый простой путь** для модерации:

- Сконвертировать `.md` → HTML через любой статический генератор (MkDocs / Jekyll / pandoc).
- Хостинг: GitHub Pages, GitLab Pages, или поддомен корпоративного сайта.
- URL должен открываться **без авторизации** и без CAPTCHA.

**Что нельзя**:
- Документ за логином / paywall'ом.
- Документ только в виде PDF на скачивание (нужна страница с просмотром).
- Документ на Google Docs / Notion (модерация регулярно отклоняет).

## 4. Что должно совпадать

- **Название приложения** в EULA = название в карточке Маркетплейса (см. `copy.md` пункт 1).
- **Реквизиты лицензиара** в EULA = контрагент в кабинете разработчика 1С-Битрикс.
- **Дата редакции** в EULA / Privacy ≤ дате сабмита (модерация может отклонить, если документ датирован «будущим» числом).

## 5. Что нужно от юриста (минимум)

1. Проверить: правильно ли вписаны реквизиты ОГРН/ИНН/КПП/юр.адрес.
2. Подтвердить: подходит ли организационно-правовая форма для подписания договора с 1С-Битрикс (УСН + ОКВЭД 62/63 — см. `requirements-checklist.md` п. 2).
3. Проверить: соответствует ли формулировка «обработки по поручению Лицензиата» (privacy-policy.md, п. 10.2) реальной модели данных Приложения. У нас она stateless — это ключевой довод.
4. Подтвердить: можно ли указанной редакцией принять Federal Law 152-ФЗ как соблюдённый.
5. Проверить: реквизиты ЭДО (Диадок) для документооборота с 1С-Битрикс.

## 6. Чек-лист до отправки на модерацию

- [ ] EULA опубликован по постоянному URL.
- [ ] Privacy Policy опубликована по постоянному URL.
- [ ] Оба документа открываются без авторизации.
- [ ] Дата редакции — не позднее дня сабмита.
- [ ] Реквизиты Лицензиара совпадают во всех документах и в кабинете разработчика.
- [ ] Название приложения в EULA совпадает с названием в карточке Маркетплейса.
- [ ] Юрист дал письменное (или хотя бы e-mail-) подтверждение.
- [ ] Контрагент создан в кабинете 1С-Битрикс, ЭДО подключён.

## 7. Если что-то меняется после сабмита

- **Замена реквизитов / переименование организации**: новая редакция документов + замена URL в карточке.
- **Изменение функционала** (например, начнём хранить данные на сервере): обновить privacy-policy.md, поднять редакцию.
- **Запуск нового региона** (BY, KZ, EN): отдельные редакции с локальным правом, отдельные URL.
