## 3. Архитектурный принцип «stateless»

3.1. Приложение спроектировано как stateless-сервис: **персональные данные сотрудников Лицензиата не хранятся на серверах Оператора**.

3.2. Все данные запросов согласования, голосов и приложенных файлов сохраняются непосредственно в Битрикс24-портале Лицензиата:
- запросы — в entity-хранилище `appr_requests`;
- голоса — в entity-хранилище `approval_votes`;
- файлы — в Bitrix24 Disk портала.

3.3. Оператор технически не имеет постоянного доступа к этим данным; обращения к Битрикс24 REST API производятся только в момент запроса от Приложения, с использованием OAuth-токенов, передаваемых клиентом.

---

## 4. Какие данные обрабатываются временно

4.1. В процессе обработки HTTP-запроса от Приложения серверы Оператора получают и **временно** обрабатывают следующие данные:

| Данные | Цель | Срок хранения |
|--------|------|---------------|
| ID пользователя Битрикс24 (числовой) | Маршрутизация запроса | Только на время одного HTTP-запроса (in-memory) |
| ID члена портала (`member_id`) | Идентификация портала | Только на время одного HTTP-запроса |
| Домен портала | Адресация Битрикс24 REST API | Только на время одного HTTP-запроса |
| OAuth access/refresh-токены | Авторизация Приложения в Битрикс24 | Передаются в JWT (60 минут) или в payload-е webhook'а; на сервере не сохраняются |
| Содержимое запроса (комментарий, ID согласующих) | Создание сущности в Битрикс24 entity | Только на время одного HTTP-запроса |
| Содержимое файлов | Загрузка в Bitrix24 Disk | Только на время загрузки; не сохраняется на сервере Оператора после успешной загрузки |

4.2. Перечисленные данные **не сохраняются** в постоянной базе данных Оператора. У Оператора отсутствует собственная СУБД с персональными данными.

## 5. Технические логи

5.1. В целях диагностики неполадок и обеспечения работоспособности Приложения серверы Оператора могут вести технические логи, содержащие:
- идентификатор операции (trace_id);
- IP-адрес сервера-источника запроса (порт Битрикс24 или iframe-фронтенда);
- временные метки;
- HTTP-статусы и метаданные запросов;
- сообщения об ошибках.

5.2. **В технические логи не записываются**: содержимое OAuth-токенов, тексты комментариев, имена и содержимое файлов, имена и e-mail сотрудников. Числовые ID (`user_id`, `member_id`) могут попадать в логи только в обезличенном виде.

5.3. Срок хранения технических логов — **не более 30 суток** (минимум 3 суток установлен регламентом Битрикс24 Маркетплейса).

6.2. Технические cookies, устанавливаемые сервером (например, `csrftoken`), используются исключительно для целей безопасности и не передаются третьим лицам.

## 8. Защита данных

8.1. Оператор применяет следующие меры защиты:
- шифрование канала связи (HTTPS, TLS 1.2+);
- подпись JWT-токенов алгоритмом HS256 с ключом длиной не менее 32 байтов;
- whitelist расширений и лимит размера для загружаемых файлов (защита от загрузки исполняемых файлов);
- регулярное обновление зависимостей и сканирование уязвимостей;
- разграничение доступа: на чтение деталей запроса имеют право только инициатор, согласующие и администратор портала.

8.2. Серверная инфраструктура размещена на территории Российской Федерации (Timeweb, г. Санкт-Петербург или иной согласованный регион).
