# Руководство по манифесту `app.json`

> ⚠️ **Важный нюанс**: Битрикс24 Маркетплейс **не использует** `app.json` напрямую — все технические настройки заполняются в кабинете разработчика через UI. Наш `app.json` — это **источник истины** для разработчиков и для будущей автоматизации (CI-проверки, бутстрап нового окружения, документация). Поля в кабинете 1С-Битрикс заполняем вручную, сверяясь с этим файлом.

Файл лежит в корне репозитория: `/app.json`.

---

## 1. Зачем нам отдельный манифест

1. **Single source of truth** для всей команды: что мы ставим в кабинет, что мы пишем в EULA, на что подписываемся в коде — должно быть согласовано.
2. **Документация** для онбординга новых разработчиков — за 30 секунд ясно, как устроено приложение.
3. **CI-проверки**: можно сравнить scope в `app.json` с реальными вызовами Bitrix24 REST в коде и упасть, если кто-то добавил `crm.*` без обновления манифеста.
4. **Подготовка к Маркетплейс CLI**: если 1С-Битрикс выкатит официальный CLI для упаковки решений — у нас уже будет манифест в общепринятом виде.

## 2. Плейсхолдеры

В `app.json` намеренно оставлены плейсхолдеры в формате `__NAME__`:

- `__APP_DOMAIN__` — публичный домен бэкенда (например, `chat-approval.example.ru`).
- `__VENDOR_DOMAIN__` — домен лендинга и legal-страниц.

Перед сабмитом в Маркетплейс эти плейсхолдеры заменяются на реальные значения. **В коде** используются ENV-переменные `VIRTUAL_HOST` и `NUXT_PUBLIC_API_URL` (см. Sprint 4).

## 3. Что куда вписывать в кабинете 1С-Битрикс

## 4. Поля, которых **нет** в `app.json`

Эти поля заполняются исключительно в кабинете и не имеют смысла в манифесте:

- Маркетинговый слоган и полное описание (см. `copy.md`).
- Скриншоты, иконка (см. `visuals-brief.md`).
- «Что нового в приложении» (см. `copy.md`).
- Реквизиты лицензиара (см. `legal/eula.md`).

Это разделение намеренное: технические параметры — в манифесте, маркетинг — в текстовых документах.

## 5. CI-проверка манифеста

(План на Sprint 4 / future.) В `.github/workflows/ci.yml` можно добавить job:

```yaml
manifest-validate:
  name: Validate app.json
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - run: |
        python <<'EOF'
        import json
        with open("app.json") as f:
            m = json.load(f)
        assert "code" in m and "." in m["code"], "code must be vendor.app"
        assert m["scope"] == sorted(m["scope"]), "scope must be sorted (canonical order)"
        assert "im" in m["scope"] and "imbot" in m["scope"], "im/imbot required"
        assert m["limits"]["file_size_max_bytes"] == 25 * 1024 * 1024
        # ...еще проверки
        print("app.json OK")
        EOF
```

Это поймает рассинхрон с кодом до того, как уйдёт PR.

## 6. Контрольный список перед заполнением кабинета

- [ ] Заменены плейсхолдеры `__APP_DOMAIN__` и `__VENDOR_DOMAIN__` на реальные значения **локально, не в репо** (репо хранит шаблон).
- [ ] `version` синхронизирована с git tag.
- [ ] `scope` совпадает с фактическим набором вызовов в коде (см. `python -m grep "self\\.client\\." backends/python/api/`).
- [ ] `placements[].handler` совпадает с тем, что фронт регистрирует в `install.client.vue`.
- [ ] `events[].handler` совпадает с маршрутами в `main/urls.py` и `approvals/views.py`.
- [ ] `bot.commands[].handler` совпадает с маршрутом `vote_handle`.
- [ ] EULA / privacy URLs открываются в анонимном браузере (без авторизации).

## 7. Изменения после первой модерации

Если меняется `code`, `version`, `scope` — нужна повторная модерация. Простые изменения (тексты, иконка) проходят быстрее.

В `app.json` храним всю историю через git: новый `version` — это новый коммит, который можно сравнить `git diff` с предыдущей версией.

## 8. Связь с другими документами

- Технические лимиты в `app.json::limits` ↔ EULA `eula.md` пункт 4.3.
- `monetization` в `app.json` ↔ `pricing.md`.
- `compliance` ↔ `legal/privacy-policy.md`.
- `placements` и `events` ↔ ARCHITECTURE.md (поток данных).

Любое изменение в `app.json` обязано быть отражено в соответствующем документе. CI-проверка из п. 5 в перспективе должна это валидировать автоматически.
