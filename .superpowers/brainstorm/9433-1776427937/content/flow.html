Флоу создания запроса и голосования

Одна форма → Django → Bitrix24. Посмотрите на последовательность шагов.

1. Создание запроса

Nuxt (форма)
→
Пользователь заполняет: комментарий, согласующие, правило, файлы
Nuxt
→
POST /api/approval/create (multipart: поля + файлы)
Django
1.
Проверить JWT, извлечь userId инициатора
Django → B24
2.
disk.folder.add — создать папку /Согласования/[ID] на общем диске
Django → B24
3.
disk.folder.uploadfile — загрузить файлы в созданную папку, получить fileIds
Django → B24
4.
entity.item.add — сохранить запрос со статусом COLLECTING
Django → B24
5.
imbot.message.add — опубликовать сообщение с кнопками в чате (Bot Platform 2.0 keyboard)
Django → B24
6.
entity.item.update — записать botMessageId обратно в запрос
Nuxt
←
200 OK → показать карточку запроса

2. Голосование (Bot Platform 2.0 webhook)

B24 (кнопка)
→
POST /api/vote/handle — {userId, messageId, action: "approve"|"reject"}
Django
1.
Найти запрос по messageId, проверить статус COLLECTING
Django
2.
Правила: инициатор не может голосовать, один голос на пользователя
Django → B24
3.
entity.item.add (votes) — записать голос
Django
4.
Пересчитать статус: REJECT → мгновенно REJECTED; порог выполнен → APPROVED
Django → B24
5.
entity.item.update — обновить статус и счётчики
Django → B24
6.
imbot.message.update — обновить бот-сообщение (счётчики + убрать кнопки если завершено)
Этот флоу выглядит правильно?

Если всё ок — перейдём к структуре Django-приложения и фронтенд-компонентам, затем запишем спеку.
